Major, test/integration/repository_previews_test.rb:113 and 122
Problem: Tests remove global permissions from Role.find(1) without restoring them, which can leak into subsequent tests within the same process if integration tests are not fully wrapped in database transactions. This can cause later repository preview tests to fail with 403 responses.
Failure scenario: If Redmine::IntegrationTest does not run each test in a DB transaction (or transactions are disabled for integration tests), test_more_preview_needs_a_repository_permission (which removes both :view_changesets and :browse_repository) runs before other tests that expect the default Manager permissions, causing those tests to receive :forbidden instead of :success and fail spuriously depending on execution order.

- role = Role.find(1); orig = role.permissions
- role.remove_permission!(:view_changesets); role.remove_permission!(:browse_repository)
- … assertions …
- ensure role.permissions = orig; role.save!
Alternatively, explicitly add the removed permissions back at the end of each test with add_permission!.
