Calling to_h on settings['converter'] when it is nil raises NoMethodError. On instances where plugin settings don’t include a 'converter' key (eg, fresh install not yet saved, or tests using with_settings that omit it), apply! will crash. Concrete failure: running rake redmine_more_previews:use_core_previews with only basic settings (no 'converter') results in NoMethodError: undefined method `to_h' for nil:NilClass. Fix: defensively default to an empty hash. For example:
  settings  = ::Setting.plugin_redmine_more_previews.to_h.deep_dup.deep_stringify_keys
  converter = settings['converter'].is_a?(Hash) ? settings['converter'] : {}
and keep the final merge as-is:

## Resolutions

1. major, `settings['converter'].to_h` on nil: **not a defect.** `NilClass#to_h` returns `{}` in Ruby,
   so a configuration without a `converter` key yields an empty hash and `apply!` returns no
   changes. Proven by `CoreHandoverTest#test_without_any_converter_settings` (settings with only
   the global keys, no `converter`): passes, no exception.
