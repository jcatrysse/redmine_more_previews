Major, converters/vince/lib/vince.rb:50-55
Vince logs exception messages and full backtraces from failed vCard previews, which can include user-controlled vCard content. This violates the “no secrets in logs” rule and can leak sensitive information into production logs.
Failure scenario: A user uploads a malformed vCard with a long NOTE field; parsing raises ArgumentError whose message includes the offending line. The server logs then contain that NOTE content and the full backtrace for every failed attempt.
Fix: Reduce logging to non-sensitive metadata. For example:
  rescue StandardError => e
    Rails.logger.warn "vCard #{File.basename(source)} not previewed: #{e.class}"
    raise
Alternatively, gate detailed logs behind a debug flag and never include user-controlled content or backtraces in production.

Resolution: not changed. The log is the server's, read by its operators, not a channel to other
users, and a vCard's content is no secret of the server (whoever may see the attachment sees it).
It is the practice of the plugin before this round: `Conversion#preview` logs `e.message` and the
backtrace of every failed conversion (seen on the old code in this round: "Exception was: broken
vCard line" with the backtrace), and Cliff logs the same since round 5 for the same reason (a parse
failure must be diagnosable; the page shows only that the file could not be previewed). Upstream
6b44d3a adds this log line because the child otherwise leaves without any message. No credential
or setting reaches it: the child's settings are read before the fork and not part of the message.
