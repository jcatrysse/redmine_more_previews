  File: lib/redmine_more_previews/patches/attachments_controller_patch.rb: within the show action, the branch handling params[:asset]
  Problem: After calling find_asset_param, the code does not return when find_asset_param has already rendered a 404 (performed? is true). If @asset is invalid (path traversal etc.), find_asset_param renders 404, but execution continues into respond_to { send_more_asset }, causing a double render (AbstractController::DoubleRenderError) or an unintended attempt to send data after a 404.
  Failure scenario: GET /attachments/more_preview/1234/index.html?asset=../../etc/passwd causes find_asset_param to render_404. The action then still enters respond_to and calls send_more_asset, raising a 500 double render instead of cleanly returning 404. This is externally triggerable and defeats the 404 hardening.

      find_asset_param
      return if performed?
      respond_to do |format|
        format.any { send_more_asset }
      end
    end

## Resolutions

1. major, attachments_controller_patch double render: **not a defect.** `find_asset_param` runs as a
   `before_action` for `more_preview` and `more_asset`; a `render_404` there halts the filter
   chain, the action never runs. `show` does not handle an asset. Proven by
   `test_asset_outside_the_preview_directory_is_refused` (404, not 500) and by the e2e probes in
   `docs/e2e/security.md`. The repository `entry` override calls `find_path_param` inline, which
   is why only that one got `return if performed?`.
2. minor, cliff Cc uses @mail.from: **not reachable, code left as is.** The mail gem returns an
   address list for Cc, never a String, so the branch is dead code; a mail with one Cc shows it
   correctly. Added `test_mail_with_one_cc_shows_the_cc` (passes before and after) to keep it so.
   A change that no test can make fail would be a drive-by edit (CLAUDE.md).
3. minor, label_debug / field_debug: **not a defect.** The settings view uses `l(:label_debug)`;
   `en`, `de`, `es`, `fr`, `ja`, `jp`, `zh` define `label_debug`; pt-BR, pt and ru had the
   misspelt `field_debug`, which is what made the label missing there. `test/unit/locales_test.rb`
   now compares every shipped locale with `en.yml`.
4. major, admin info test needs pandoc: **partly accepted.** The checked label is the same text
   whether pandoc is found or not (only the icon differs), so that test does not depend on it. But
   the markdown and textile tests do need pandoc, and the manual workflow did not install it:
   fixed in the workflow (pandoc for the tests; LibreOffice, ImageMagick, Ghostscript for the e2e
   run), commit below.
5. minor, CSP must start with sandbox: **fixed**, the tests now accept the directive anywhere in
   the header.
