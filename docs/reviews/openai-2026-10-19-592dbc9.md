blocker, lib/redmine_more_previews/lib/rmp_process.rb:~113
Undefined local variable “now” when computing the child wait deadline. In fork(timeout:, memory:), the code calls: status = watch(pid, now + timeout, memory). The variable now is not defined in this scope, causing a NameError at runtime whenever a conversion uses RmpProcess.fork (e.g., Cliff’s forked email parsing), resulting in a 500 instead of proper timeout/refusal handling.
Failure scenario: Open an .eml attachment to view its headers/body (Cliff). The preview path triggers RmpProcess.fork; Rails logs show “undefined local variable or method `now’ for RedmineMorePreviews::Lib::RmpProcess:Module” and the request fails with 500.
Fix: Replace now with Time.now (or define a local deadline before watch). Example:
- status = watch(pid, now + timeout, memory)
+ status = watch(pid, Time.now + timeout, memory)
Alternatively: deadline = Time.now + timeout; status = watch(pid, deadline, memory)

Resolution: not a defect. `now` inside `def self.fork` is the module method `RmpProcess.now`
(rmp_process.rb, `def self.now`: `Process.clock_gettime(Process::CLOCK_MONOTONIC)`); `Time.now`
would mix wall-clock time with the monotonic deadlines of `watch`. The line is unchanged since
round 5 (`8202ac6`, line 103). Run on every Cliff conversion: rmp_process_test (fork, time limit,
refusal through the pipe) and the e2e scenarios mail, limits and round6_files pass.
